# Decisions

Source of truth for the migration decisions. D1-D20 are copied from the approved plan §2 (verbatim except that references to the previous chain read "previous program/chain", so this file passes the purge check) (confirmed by the owner on
2026-10-10; D1, D2, D3, D4, D5, D6, D12 and D17 were confirmed explicitly in the plan checkpoint and the implementation brief). Forced deviations discovered while implementing are appended below as
`X<n>` entries with the evidence (doc link or measurement); the decision itself is never reopened silently.

## Approved decisions (plan §2)

Slug stays the public identifier in API/MCP/web; DB `agents.id` keeps the 32-hex id. | PACKAGE_SPEC §4.1, every manifest, DB keys and MCP ids already use this id; keccak(slug) would add a second id everywhere for no gain. | D2 | UUPS proxies (OZ v5 `UUPSUpgradeable` + `Initializable`, ERC-7201 namespaced storage, `openzeppelin-foundry-upgrades` layout validation in CI) for all six contracts; upgrader = ADMIN (cold). | The license NFT address must stay stable; the team ships fixes weekly; the previous program was upgradeable too. | D3 | Fee sponsorship: the platform runs its own relay inside the Express server (`POST /api/relay`, viem `Relay.create` + `Relay.feePayer({ account: RELAY key, feeToken: PAYMENT_TOKEN, validate })`). RELAY is a dedicated hot key that only pays fees (no contract roles, separate from PLATFORM). `validate`: type 0x76, our chain id, fee-payer slot unsigned, 1..4 calls all `value == 0`, `to ∈ our 6 contracts` or (`to == PAYMENT_TOKEN` and selector ∈ {approve, permit} with decoded spender ∈ our contracts), `gasLimit <= RELAY_MAX_GAS_PER_TX`, `validBefore <= now + 120 s`, sender == session wallet (JWT) with per-wallet/IP daily gas quotas, then simulate and refuse reverts (a sponsored revert still burns fees); co-sign, broadcast, log to `relay_log`. Browsers and agents send 0x76 txs with `feePayer: true`. Server-side txs use `feePayer: Account` in-process with 2D nonce lanes (`nonceKey` 1 = PLATFORM `*For`, 2 = VERIFIER, 3 = usage batches, 4 = admin; lane allocator + `sent_txs(lane, nonce, hash, status)`, `next` recovered from chain at boot, `validBefore` lets a stuck tx expire). `FEE_PAYER_URL` can point to `https://sponsor.moderato.tempo.xyz` in dev. | D5 | Money movement in contracts: push creator/treasury shares straight from the payer at purchase (`_pullTo`); if the push to a recipient fails for recipient-side reasons (TIP-403/receive policy), pull the amount into the contract (balance-diff checked, rejects fee-on-transfer) and credit `deferred[recipient]` (pull fallback, `claim()`), so a creator's wallet policy can never block a sale or a release; vault deposits (escrow, stake) are always balance-diff checked. Details in §4.0. | Push-at-purchase is required; receive policies are a documented Tempo behaviour (T5). |
| D6 | Eval score is version-scoped, never zeroed: `setEval(agentId, versionHash, scoreBps, evalHash)` stores the versionHash it measured; `updateVersion` leaves it untouched; readers treat `eval.versionHash != agent.versionHash` as "not measured for this version". Label rule unchanged ("internal team test", never "verified"). | Resolves the `update_version` zeroing problem explicitly. |
| D7 | Auth: SIWE (EIP-4361) via `viem/siwe` for web, OAuth consent page (EIP-6963 injected wallets) and agent keypair login; nonces/TTL/domain checks as today; JWT (`jose`) unchanged.
